## 2. 🚧 Skill Boundaries: What is vs What isn't

基于 8 家文档的共识，我们对 Skill 的边界定义如下：

### ✅ IS A SKILL (它是技能)
*   **Encapsulated Workflow (封装工作流)**: 包含明确步骤的任务。
    *   *例*: "Deploy to AWS", "Refactor to React Hooks".
*   **Tool-Augmented (工具增强)**: 需要调用脚本来完成任务。
    *   *例*: "Visualize Codebase" (调用 Python 生成 HTML), "Security Scan" (调用 Trivy).
*   **On-Demand Knowledge (按需知识)**: 只有特定任务才需要的冷知识。
    *   *例*: "Migration Guide v2 to v3", "Legacy System Docs".

### ❌ IS NOT A SKILL (它不是技能)
*   **Global Preferences (全局偏好)**: 应该放进 `System Prompt` 或 `Custom Instructions`。
    *   *例*: "Always speak Chinese", "Be concise".
    *   *Windsurf Explicit Rule*: "Use Skills for tasks, Rules for behaviors."
*   **Simple Aliases (简单别名)**: 如果只是把一句话变成快捷键，不配叫 Skill。
*   **Always-On Context (常驻上下文)**: 项目的核心架构文档应直接放在 Context 中（或 `.cursorrules`），而不是 Skill。

## 3. Saki's Strategic Positioning

鉴于上述分析，Saki 的架构设计 (`saki.py` + Indexing) 是完全符合且领先于标准的：

1.  **Universal Injection (通用注入)**:
    Saki 选择生成标准的 `SKILL.md`，这意味着 Saki 生成的技能 **可以同时在 Claude, Cursor, Windsurf, Antigravity 中运行**。
    *   *Action*: 我们应该在 `bootstrap` 时检测 IDE 类型，把文件写到对应的目录（`auto-detect`）。

2.  **The "Factory" Advantage**:
    大多数 Agent 只能"读取" Skill，而 Saki 能"生产" Skill。
    *   Antigravity 想要你手写 `SKILL.md`。
    *   **Saki 帮你写 `SKILL.md`**，而且是基于 3,500+ 个最佳实践写的。

### 结论
**Skill = The "App" Model for Agents.**
**Saki = The "App Store" + "Factory".**
